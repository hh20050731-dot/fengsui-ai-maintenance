# 飞书原生协同：明日手动配置清单

> 本清单基于 2026-07-19 的实际检查结果：开放平台入口可访问，但当前内置浏览器停留在扫码登录页。唯一安全截图为 [`blocked-sensitive-step.png`](../artifacts/computer-use/blocked-sensitive-step.png)，已裁掉二维码区域。

## 1. 登录与进入应用

1. 用户本人访问 `https://open.feishu.cn/app`。
2. 在飞书移动端完成扫码登录。此步骤今天被安全限制阻塞，自动化没有操作二维码。
3. 在开发者后台进入现有“烽燧智守”企业自建应用。
4. 确认应用名称、所属企业和应用类型正确，不新建重复应用。

## 2. 启用并检查机器人

1. 打开应用的“应用能力”或“机器人”页面。
2. 确认机器人能力已启用；如果未启用，由用户本人点击启用并阅读影响范围。
3. 不要在此阶段发布正式版本。
4. 在飞书运维群中通过“群设置 → 群机器人/添加机器人”添加该应用机器人。
5. 若机器人不在应用可用范围，先检查版本可用范围和企业管理员审批，不扩大范围到无关成员。

## 3. 权限最小化确认

按飞书后台当前显示的正式权限名称确认，不根据旧文档猜测权限字符串。最小能力目标为：

- 以应用身份发送单聊或群组消息；
- 接收群内 @ 机器人消息或机器人单聊消息；
- 读取当前应用机器人所在群的必要会话信息；
- 读写目标多维表格中的维修工单记录；
- 如需用户姓名，再申请最小的用户基础信息权限。

涉及敏感权限、通讯录批量权限或扩大应用可用范围时暂停，交由企业管理员审批。

## 4. 获取群 chatId

优先使用官方可追溯方式：

1. 将机器人加入目标运维群。
2. 在群内 @ 机器人发送一条测试文本。
3. 从已配置的 `im.message.receive_v1` 事件体中的 `message.chat_id` 获取 chatId，或使用飞书后台当前官方文档提供的群列表接口。
4. 将值写入部署平台服务端环境变量 `FEISHU_NOTIFICATION_CHAT_ID`。
5. chatId 不写入前端、不硬编码到源码、不写入截图或公开文档。

## 5. 配置事件与回调

1. 打开“开发配置 → 事件与回调”。
2. 选择将事件发送至服务器的 Webhook 方式。
3. 回调地址填写：`https://<测试域名>/api/feishu/events`。
4. 添加事件：接收消息 `im.message.receive_v1`。
5. 添加回调：卡片回传交互 `card.action.trigger`。
6. URL 校验会发送 challenge；当前接口已支持明文与 Encrypt Key 加密后的 challenge。
7. 不使用本地 `localhost` 作为正式回调地址；测试域名必须 HTTPS 且可由飞书服务器访问。

## 6. Verification Token 与 Encrypt Key

1. 在“事件与回调 → 加密策略”查看 Verification Token 和 Encrypt Key。
2. 不在截图、聊天、终端日志或文档中显示明文。
3. 仅由用户本人写入部署平台的服务端环境变量：
   - `FEISHU_VERIFICATION_TOKEN`
   - `FEISHU_ENCRYPT_KEY`
4. 当前服务端会校验 Verification Token；配置 Encrypt Key 后使用官方 SDK 同算法的 AES-256-CBC 方式解密。

## 7. 维修工单多维表格

1. 打开当前工单多维表格，确认字段名称仍为：工单编号、设备名称、设备编号、故障部位、故障类型、风险等级、工单状态、创建时间。
2. 不改变现有字段结构，不新建同名重复表。
3. 将多维表格 app token 和工单 table id 仅写入服务端环境变量：
   - `FEISHU_BITABLE_APP_TOKEN`
   - `FEISHU_WORK_ORDER_TABLE_ID`
4. 其他业务表未配置时保持模块级 Mock 降级，不影响工单飞书能力。

## 8. 自动督办与日报

1. 生成至少32位随机值作为 `CRON_SECRET`，只放在服务端和定时任务平台。
2. 定时调用：
   - `POST /api/jobs/work-order-reminders`
   - `POST /api/jobs/daily-operations-brief`
3. 使用 `Authorization: Bearer <CRON_SECRET>` 或 `x-cron-secret` 请求头。
4. 不在 URL 查询参数中传密钥。

## 9. 发布前检查

1. 在测试环境调用 `/api/integration/status`，确认 `workOrders.mode = feishu`、`workOrders.configured = true`。
2. 确认机器人能力、消息权限、事件、回调和目标群均已配置。
3. 由用户本人创建测试版本，选择最小可用范围并提交审批。
4. 正式发布属于高风险步骤，今天没有自动执行。

## 10. 真实验收顺序

1. 在 3D“轴承温升”场景创建一张新的高风险工单。
2. 检查飞书多维表格出现新工单，字段映射正确。
3. 检查运维群收到高风险工单卡片。
4. 点击“确认接单”，确认网站状态机执行“待接单 → 已接单”。
5. 检查卡片更新为“已接单”，多维表格“工单状态”同步更新。
6. 在群内依次测试七类机器人问题，确认答案意图和数据不同。
7. 用受保护接口触发一次督办和日报测试。
8. 检查失败通知不会回滚工单，日志不含 Secret、Token 或完整回调载荷。

## 11. 需要填写的服务端环境变量

- `APP_MODE=feishu`
- `APP_BASE_URL`
- `FEISHU_APP_ID`
- `FEISHU_APP_SECRET`
- `FEISHU_VERIFICATION_TOKEN`
- `FEISHU_ENCRYPT_KEY`
- `FEISHU_BITABLE_APP_TOKEN`
- `FEISHU_WORK_ORDER_TABLE_ID`
- `FEISHU_OPERATION_LOG_TABLE_ID`（推荐；用于跨 Serverless 实例保存回调与督办幂等标记）
- `FEISHU_NOTIFICATION_CHAT_ID`
- `CRON_SECRET`

不得在 `VITE_` 开头的前端变量中放 App Secret、Token、Encrypt Key 或 CRON_SECRET。
