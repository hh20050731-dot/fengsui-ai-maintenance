# 安全审计报告

## 结论

本轮未发现被 Git 跟踪的真实 Secret、Token、Cookie、二维码或环境文件。生产依赖审计结果为 0 个已知高危漏洞。

| 检查项                                    | 结果                                            |
| ----------------------------------------- | ----------------------------------------------- |
| `.env` / `.env.local` / `.env.*`          | 已忽略，仅 `.env.example` 可提交                |
| App Secret / API Key                      | 仅由服务端环境变量读取，前端无对应变量          |
| Tenant token                              | 服务端获取与缓存，日志不输出完整令牌            |
| 飞书写入失败                              | 不回放到 Mock，不用模拟成功掩盖真实失败         |
| E2E真实数据隔离                           | 强制 `forceMock`，不复用外部服务                |
| 写操作校验                                | Zod 校验；工单与库存使用幂等键                  |
| HTTP基础防护                              | Helmet、关闭 `x-powered-by`、统一错误处理中间件 |
| 定时任务                                  | `CRON_SECRET` 保护，支持 Bearer 或专用请求头    |
| `npm audit --omit=dev --audit-level=high` | `found 0 vulnerabilities`                       |

## 数据与模型边界

- 所有监测、趋势、健康度、故障概率和诊断结论均明确标注为比赛模拟数据。
- 规则匹配度不是模型准确率。
- 多模态本地模式不声称已识别图片中的真实缺陷。
- 语义3D模型不是厂家精确 CAD，不用于制造、安装或安全校核。

## 仍需平台侧控制

- Vercel、飞书、豆包、Aily、妙搭密钥与审批只能由账号管理员完成。
- 正式飞书权限应继续按最小权限配置，并在开放平台发布前复核。
- 生产环境需配置 HTTPS、回调来源校验、告警日志留存和企业安全审计策略。
