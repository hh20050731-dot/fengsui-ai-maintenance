# 产品与业务洞察

## 产品定位

“烽燧智守”面向垃圾焚烧发电厂关键旋转设备，把分散的监测数据、规则研判、知识经验、三维定位、维修工单、备件库存与飞书协同串成一条可追溯闭环。比赛版本使用可复现模拟数据和可解释规则模型；飞书维修工单写入与状态同步可在凭证完备时真实联调。

## 关键业务洞察

1. 固定阈值缺少工况语境。设备启动、高负荷和稳定运行的合理区间不同，因此演示规则先识别工况，再选择基准并计算偏离。
2. 单指标告警难以直接指导检修。系统把振动、温度、电流、压力和转速融合为贡献度，保留原始趋势证据，避免只给一个不透明分数。
3. 诊断结论若不进入工单，就不能形成管理闭环。Agent 的价值不在“聊天”，而在按受控工具链读取状态、检索知识、检查库存并建议或创建工单。
4. 现场理解成本高。语义数字孪生用部件节点、故障定位和 LOD 模型降低沟通成本，但明确不是厂家级 CAD，也不承担制造或安全校核。
5. 维修经验容易流失。工单完成后形成知识候选，保留设备、故障、处置、备件和验证结果的关联 ID，支持后续审核沉淀。

## 竞品与替代方案对比

| 维度          | 传统固定阈值监控 | 普通设备管理系统 | 单一故障诊断系统 | 烽燧智守                                           |
| ------------- | ---------------- | ---------------- | ---------------- | -------------------------------------------------- |
| 工况适应      | 弱               | 通常不包含       | 依赖具体产品     | 演示规则按停机、启动、低负荷、稳定、高负荷切换基准 |
| 多参数融合    | 少量             | 弱               | 中到强           | 振动、温度、电流、压力、转速统一贡献度             |
| 可解释性      | 阈值可见         | 流程可见         | 视模型而定       | 趋势、规则、RAG引用、Agent步骤摘要可追溯           |
| 3D定位        | 通常无           | 通常无           | 可选             | 9类语义模型、三档LOD、节点高亮与壳体控制           |
| RAG / Agent   | 无               | 无               | 少量             | 本地可追溯RAG与十工具MaintenanceAgent              |
| 飞书协同      | 通常无           | 消息集成         | 通常无           | 多维表格工单、机器人、卡片和长连接适配             |
| 工单/备件闭环 | 弱               | 强               | 弱               | 状态机、幂等扣减、验证恢复和知识候选               |
| 部署成本      | 低到中           | 中到高           | 高               | 比赛原型可Mock独立运行，真实模块按能力逐步启用     |
| 实施难度      | 低               | 中               | 高               | 原型低；生产化仍需真实数据治理、模型验证与安全审批 |

## 价值量化边界

本项目不宣称已经在真实焚烧厂降低故障率、缩短停机时间或获得经济收益。可用于后续试点的量化框架如下：

| 指标           | 计算方式                                | 来源类型              | 当前状态                            |
| -------------- | --------------------------------------- | --------------------- | ----------------------------------- |
| 告警到接单时长 | 接单时间－预警确认/工单创建时间         | 项目目标              | 演示可计算，真实基线待企业提供      |
| 工单按时闭环率 | 时限内完成工单数/完成工单总数           | 项目目标              | 演示流程可验证，不代表生产绩效      |
| 重复故障识别率 | 命中历史相似案例的重复事件/重复事件总数 | 演示测算              | RAG可演示，真实准确率待标注数据验证 |
| 备件缺料拦截数 | 因库存不足被阻止完成的工单数            | 项目目标              | 规则与测试已覆盖                    |
| 非计划停机损失 | 停机时长×机组边际收益/成本参数          | 行业公开数据+企业数据 | 未计算；需要真实经营口径            |

## 分阶段落地路径

1. 比赛原型：模拟遥测、规则健康度、本地RAG、语义3D、Mock闭环与飞书工单联调。
2. 单场站试点：接入历史数据和只读实时数据，校准工况基准，开展影子运行和人工复核。
3. 受控协同：在审批后启用通知、工单写入和移动巡检，保留人工确认开关。
4. 规模化：建设数据质量、模型监控、权限审计、灾备和跨场站知识治理；在验证后再评估预测模型。
