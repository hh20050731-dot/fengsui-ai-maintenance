## 1. 页面

1. **首页**：今日已完成巡检、今日异常巡检、待处理工单、飞书通知状态、严重预警和低库存备件。
2. **设备巡检**：设备、运行状态、振动、温度、压力、电流、异常描述、现场照片和真实提交结果。
3. **异常上报**：从新巡检记录开始，支持图片、多模态辅助研判、生成预警和创建维修工单。
4. **我的工单**：按主系统现有待接单、已接单、检修中、待验证、已完成状态查看。
5. **工单详情**：AI 诊断、建议备件、处理记录、来源巡检、飞书卡片状态、主动重发、3D 和网页版跳转。
6. **巡检详情**：展示保存模式、规则原因、预警和工单关联，并提供幂等业务动作。

## 2. 巡检记录与可选飞书表

主服务统一使用 `InspectionRecord`，包含巡检编号、设备、巡检人、时间、运行状态、振动、温度、压力、电流、异常描述、图片引用、风险等级、AI 摘要、状态和关联编号。

巡检状态为：`草稿`、`已提交`、`已生成预警`、`已生成工单`、`已关闭`。

- 未配置 `FEISHU_INSPECTION_TABLE_ID` 时，记录真实写入现有服务端 Repository，不阻断提交。
- 配置该变量后，主服务会把巡检记录写入当前 `FEISHU_BITABLE_APP_TOKEN` 指向的同一个 Base 内指定数据表。
- 系统不会自动创建、删除或修改飞书数据表；管理员需人工建立字段兼容的数据表并配置表 ID。
- 图片仅保存 HTTPS 资源地址或 `attachment://`、`file_token:` 附件引用，不把 Base64 写入多维表格。
- 本地 Repository 可满足 Mock 和服务进程内的真实读写；Vercel 冷启动间的长期保存应配置巡检数据表。

## 4. 业务闭环

```text
InspectionRecord
  -> Alert（复用现有结构和 Repository）
  -> WorkOrder（复用现有创建服务和状态机）
  -> FeishuBitableRepository（复用原工单表）
  -> 机器人交互卡片（复用原卡片构建器）
```

- 预警条件：人工标记异常、风险为关注及以上、参数超过当前设备演示阈值，或多模态建议人工检查。
- 预警以 `inspectionId` 建立确定性关联；不提供或伪造模型准确率。
- 工单保存 `inspectionId` 和 `alertId`，重复点击返回已有对象，不重复生成。
- 飞书工单表写入失败时沿用现有本地保留/同步状态机制。
- 配置 `FEISHU_NOTIFICATION_CHAT_ID` 时，主服务发送真实交互卡片并保存消息引用；工单状态变化更新原卡片。
- 未配置通知群时，工单继续成功，`notificationStatus=not_requested`，页面显示“工单已创建，通知群未配置”。
- “重新发送飞书卡片”只在用户主动点击时调用服务端接口。

## 5. 图片和 AI

- 支持 JPG、PNG、WebP，客户端限制 8 MB；主多模态接口继续执行服务端类型和大小校验。
- 图片先调用现有多模态接口辅助研判，再上传妙搭文件存储；巡检记录只保存安全资源引用。
- AI 结果明确标注为辅助判断，不替代现场检测和专业人员判断。
- RAG、Maintenance Agent、健康评分、Three.js 和 GLB 均继续由现有主系统负责。

## 6. Preview 前置项

1. 先把根仓库和妙搭仓库的功能分支推送完成。
2. 确认 Preview 可见范围：当前开发账号，以及明确列出的测试成员。
3. 若主服务尚无可访问的 Preview API，先创建 Vercel Preview，并把非敏感 URL 配置为妙搭 `FENGSUI_CORE_API_BASE_URL`。
4. 将经验证的妙搭功能提交快进到 `sprint/default` 后才能执行 `release-create`。
5. 只创建测试 Preview，不执行正式发布，也不合并主系统 `main`。
