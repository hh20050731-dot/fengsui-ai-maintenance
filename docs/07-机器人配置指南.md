# 07 机器人配置指南

## 开启与授权

1. 在应用能力中开启“机器人”。
2. 申请并审核 `im:message:send_as_bot`（以应用身份发消息）。
3. 把机器人加入目标群，或确认应用可向目标用户发消息。
4. 获取目标 `chat_id`，写入服务端 `FEISHU_NOTIFICATION_CHAT_ID`。代码不硬编码任何群/用户 ID。

## 消息行为

- Mock：返回交互卡片 JSON 并在系统设置显示预览，不发送真实消息。
- Feishu：服务端调用 `POST /im/v1/messages?receive_id_type=chat_id`，发送 `interactive` 卡片。
- 卡片包含设备、工况、健康度、风险、异常指标、疑似原因、时限和“模拟演示数据”。
- 发送失败只返回可重试结果并记录错误说明，不回滚预警/工单等业务写入。

## 回调

事件 URL：`https://你的域名/api/feishu/events`。

接口支持 URL challenge、Verification Token 来源校验、`event_id`/消息 ID 幂等，并处理“确认预警”“生成工单”卡片动作。配置 `FEISHU_ENCRYPT_KEY` 后，服务端按飞书官方 Node SDK 使用的 AES-256-CBC 兼容方式解密加密信封；未配置校验 Token 时回调端点默认关闭，不会放行未知来源。

卡片采用飞书卡片 JSON 2.0。卡片交互回调必须在飞书要求的时限内返回；上线前需要在真实测试应用中验证卡片渲染、`card.action.trigger` 结构、3 秒响应时限和重复投递。Serverless 多实例下如需跨实例持久幂等，还应配置 `FEISHU_OPERATION_LOG_TABLE_ID`。参考：[飞书卡片回传交互](https://open.feishu.cn/document/feishu-cards/card-callback-communication?lang=zh-CN)、[飞书 Node SDK](https://github.com/larksuite/node-sdk)。

卡片 URL 按 `APP_BASE_URL` 生成。确保该域名为 HTTPS、已配置 H5 可信域名并可从飞书客户端访问。比赛原型仅使用回调中可信用户标识的脱敏摘要记录操作人，不保存原始用户 ID；生产化必须结合组织角色和数据权限做细粒度授权。

## 测试

系统设置 → 发送测试消息。Mock 显示预览；Feishu 模式发送到配置会话。失败时检查机器人是否入群、应用可用范围、权限审核、会话 ID 和 tenant token。
