# 技术实现与关键模块

## 1. 前端技术栈

React 19、TypeScript、Vite、React Router、TanStack Query、React Hook Form、Zod、Tailwind CSS、Recharts、Lucide React。路由定义在 `apps/web/src/App.tsx`，统一布局位于 `layouts/MainLayout.tsx`，API与浏览器离线降级分别位于 `services/api.ts` 和 `services/offline-api.ts`。

## 2. 后端技术栈

Node.js、TypeScript、Express 5、Zod、Helmet、CORS、Cookie Parser 和 tsup。应用工厂 `apps/server/src/app.ts#createApp` 同时支持普通Node服务和Vercel Function入口；所有主要写接口使用Zod校验，异常由 `middleware/errors.ts` 转换为统一响应，不返回内部堆栈。

## 3. 共享规则模块

`packages/shared` 输出领域类型、Zod Schema、Mock数据、健康算法、工单状态机、意图路由和规则诊断。包入口只指向 `dist/index.js` 和 `dist/index.d.ts`，根构建先编译shared，避免Vercel运行时直接解析TypeScript源码。

## 4. 健康度计算逻辑

`packages/shared/src/health.ts` 维护五类工况基准和风机、水泵、发电机、减速机的差异化权重。`calculateIndicatorDeviation` 计算偏离，`calculateContributions` 形成五项指标贡献，`calculateHealthScore` 用加权惩罚得到0—100分，并用 `determineRiskLevel` 结合关键越限分级。代码明确标注其为比赛演示规则模型。

## 5. 故障诊断规则

`packages/shared/src/intent-router.ts` 识别最高风险、高风险列表、设备状态、异常指标、待处理工单、备件可用性、检修优先级、诊断原因、重复预警和兜底意图。`diagnosis.ts#buildRuleBasedDiagnosis` 仅查询意图所需数据，并输出风险判断、工况、指标、趋势、原因、检查项、时限、备件、规则匹配度和风险提示。飞书文本先由 `feishu-message-text.ts#normalizeFeishuMessageText` 解析JSON和清理mention。

## 6. 工单状态机

`packages/shared/src/workflow.ts` 固化合法迁移：待接单可接单或取消，已接单进入检修中，检修中进入待验证，待验证可退回检修中或完成。`OperationsService.transitionWorkOrder` 校验必填结果、库存和幂等键；已完成工单不再推进。

## 7. Repository适配器

`apps/server/src/repositories/data-repository.ts` 定义设备、遥测、预警、工单、备件、知识和日志的统一接口。`MockRepository` 提供完整演示数据；`FeishuBitableRepository` 继承Mock并按模块能力覆盖真实表操作。飞书工单查询和更新优先使用 `recordId`，再回退内部ID和工单编号。

## 8. Mock与Feishu模式

`apps/server/src/config/env.ts` 将客户端基础配置和各业务表配置分离。APP_MODE为feishu时，只要基础客户端可用即可启用飞书；缺少某张表只让对应能力保持Mock，不使整个系统降级。`GET /api/integration/status` 返回每个模块的 `configured` 与 `mode`。浏览器离线模式使用localStorage持久化演示工单、设备、预警、库存和知识候选，系统设置提供二次确认重置。

## 9. 飞书多维表格集成

`providers/feishu-client.ts` 在服务端获取并缓存 `tenant_access_token`，日志不输出完整令牌。`FeishuBitableRepository` 实现表记录列表、创建、单条读取和更新，工单字段通过 `toFeishuWorkOrderFields`/`fromFeishuWorkOrderFields` 映射。初始化字段模板位于 `config/bitable-schema.json`，脚本位于 `scripts/bootstrap-bitable.ts` 与 `scripts/seed-bitable.ts`。

## 10. 飞书机器人长连接

`apps/server/src/feishu-ws.ts` 使用官方 `@larksuiteoapi/node-sdk` 创建 `WSClient`，注册 `im.message.receive_v1` 和新版 `card.action.trigger`。`feishu-ws-bridge.ts` 将事件转换为可信回调格式，使用受控队列异步处理；`FeishuCallbackService` 复用IntentRouter、工单状态机和幂等日志。`POST /api/feishu/events` 继续支持Webhook challenge、Token校验和加密信封备用入口。

## 11. 3D数字孪生

`apps/web/src/features/digital-twin/` 使用Three.js、React Three Fiber和Drei加载本地GLB。默认模型 `induced-draft-fan-enhanced-v1.glb` 包含机壳、叶轮、电机、轴系、联轴器、轴承定位器和旋转轴线等语义节点；`semanticNodeMapping.ts` 负责节点校验与查找，`modelRuntime.ts` 负责材质恢复、机壳透明/隐藏、防护罩显示和资源释放。原模型仍可通过 `?model=original` 回退。

## 12. 测试与质量保障

Vitest覆盖健康度、风险、工况、意图路由、规则诊断、状态机、库存、幂等、飞书Repository、回调、长连接桥接、自动任务、离线持久化和3D语义节点。Supertest覆盖API；Playwright用例 `e2e/demo-flow.spec.ts` 覆盖演示闭环。根命令提供lint、typecheck、test、build和production产物验证。

## 13. 部署方式

本地可用 `npm run dev` 同时启动Web和Node服务，`npm run preview -- --host 0.0.0.0` 预览生产前端。`vercel.json` 将 `/api/*` 路由到Function，将非API路径回退到SPA，并显式包含shared构建产物。EdgeOne Pages备用部署仅发布前端静态产物并启用演示模式，详见 `docs/14-EdgeOne-Pages备用部署指南.md`。

## 14. 数据安全与密钥保护

真实App Secret、访问令牌、Verification Token、Encrypt Key和CRON_SECRET只从服务端环境读取；前端只允许公开App ID和运行模式。回调使用常量时间Token比较、可选AES解密、event/message幂等和脱敏日志。关键写操作使用Zod校验和幂等键；通知失败不会回滚已成功的工单写入。
