# 故事化 Demo 主线

## 一句话开场

凌晨高负荷运行期间，1号引风机的振动与轴承温度持续抬升；烽燧智守把“发现异常”一直推进到“工单、备件、验证和知识沉淀”，而不是停在一条告警上。

## 演示路径与证据

| 节点     | 演示动作                                   | 页面证据                           | 要表达的能力                                       |
| -------- | ------------------------------------------ | ---------------------------------- | -------------------------------------------------- |
| 1. 发现  | 打开设备总览，定位1号引风机预警节点        | 总览统计、拓扑风险节点             | 数据汇总与业务场景识别                             |
| 2. 解释  | 进入设备详情，查看健康度68、振动与温度贡献 | 24h趋势、贡献度、工况              | 可解释健康评估，不是黑盒分数                       |
| 3. 检索  | 在辅助研判运行RAG，查看知识片段和引用编号  | 命中文档、相似度、来源             | 结论来自仓库内可追溯资料                           |
| 4. 编排  | 运行MaintenanceAgent                       | 工具步骤摘要、外部证据、风险结论   | AI调用数据、知识、库存和工单工具，不展示隐藏思维链 |
| 5. 定位  | 进入3D数字孪生并切换轴承温升场景           | 驱动端轴承高亮、壳体透明、趋势联动 | 从“设备异常”穿透到“部件位置”                       |
| 6. 处置  | 检查轴承与润滑油库存，创建维修工单         | 库存状态、工单编号、飞书模式标识   | 风险进入真实业务对象；凭证不足时明确演示降级       |
| 7. 闭环  | 推进待接单→已接单→检修中→待验证→已完成     | 轨道式状态机、处理记录             | 业务状态受控推进、完成不可重复提交                 |
| 8. 验证  | 输入维修后指标，健康度由68恢复至92         | 当前健康度、预警关闭原因           | 触发时数据与当前数据明确区分                       |
| 9. 联动  | 查看风机轴承库存6→5                        | 备件流水、幂等键                   | 库存真实由状态驱动，重复完成不重复扣减             |
| 10. 沉淀 | 打开知识库候选案例                         | 设备、故障、处理、验证关联         | 维修结果反哺知识闭环                               |

## 真实性口径

- 遥测、健康度、风险概率、诊断结论和经济价值均为比赛模拟或目标口径。
- 当前健康算法是可解释规则模型，不宣称为经过生产验证的工业AI模型。
- 3D模型是轻量语义数字孪生，不是厂家级CAD。
- 飞书工单在服务器凭证及工单表配置完整时可以真实写入；其他未配置模块独立使用Mock，不伪装为真实成功。
- 是否停机必须由现场负责人依据安全规程、设备说明书和现场检查决定。
